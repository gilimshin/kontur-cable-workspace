# Контур: исполнительная документация КЛ

Рабочее пространство для подготовки исполнительной документации по КЛ-0,4 кВ. Исходная книга используется как образец модели данных и расчётов.

## Облачная версия на Vercel

`public/` содержит интерфейс, `api/workspace.js` — серверный API Node.js 22. Для установки: `npm ci`; проверки: `npm test && npm run build`.

Рабочие данные в облаке хранятся в **приватном** Vercel Blob (`kontur/workspace.json`), а не в файловой системе функции. Чтение идёт с `useCache: false`, запись использует условие `ifMatch` по ETag. Изменение объекта и запись события сохраняются одним атомарным обновлением. Это архитектура небольшого MVP, с лимитом 8 МБ на рабочее пространство. Для большого числа объектов, поиска и независимых прав доступа необходим PostgreSQL.

Переменные production: `WORKSPACE_PASSWORD` (случайный пароль не короче 24 символов) и подключение приватного Blob через `BLOB_READ_WRITE_TOKEN` либо поддерживаемый SDK OIDC. При отсутствии пароля сервер закрывает доступ с ответом 503. Не подключайте production-хранилище к непроверенным preview-веткам.

Вход выдаёт подписанную cookie на 7 дней с HttpOnly, Secure и SameSite=Strict. Смена общего пароля аннулирует существующие сессии. Общий пароль не заменяет персональные учётные записи и роли. Публичны только статические файлы интерфейса, данные API требуют входа. Не включайте реальные данные, пароли, `.env`, SQLite и превью объекта в Git или публичные файлы деплоя.

Миграция локальных данных выполняется отдельно после разрешения на подключение хранилища. Локальная SQLite и облачное хранилище после переноса независимы; автоматической двусторонней синхронизации нет.

## Запуск

Из этой папки выполните `python3 server.py`, затем откройте http://127.0.0.1:8765. Достаточно Python 3.9 или новее. Внешние зависимости не нужны. Сервер слушает только loopback; доступ с компьютеров коллег пока не включён.

При первом запуске импортируется предоставленная книга из Downloads, если она доступна. При последующих запусках используются сохранённые данные. Если книги нет, можно создать пустой объект. База SQLite: `data/workspace.sqlite3`. Для резервной копии остановите сервер и скопируйте эту базу. Выгрузка JSON в интерфейсе содержит один объект; обратная загрузка JSON пока не реализована.

## Границы первой версии

| Возможность | Реализация |
| --- | --- |
| Несколько объектов | Создание, переключение, реквизиты, ответственный и статус |
| Кабельные линии | Добавление, редактирование, удаление с подтверждением, поиск и расчёт длин |
| Материалы | Наименование, изготовитель, количество, паспорт и отметка ручной сверки |
| Даты | Этапы, начало и окончание, примечания; проверка порядка дат при сохранении |
| Совместная подготовка | Заметки, подпись автора, журнал событий, отказ перезаписи устаревшей версии |
| Документы | Три упрощённых черновика: кабельный журнал, ведомость кабеля, реестр этапов; печать через браузер |
| Проверки | Ответственный, шифр проекта, дата свидетельства относительно ПНР, материалы на сверке |

Имя автора — подпись сессии, не авторизация. Нет ролей, уведомлений, автоматической синхронизации открытых окон, файлов паспортов, официальных протоколов испытаний, согласования или электронной подписи. История фиксирует разделы изменений, но не является системой версий документов и не поддерживает откат. При конфликте сохранения интерфейс просит сохранить свои правки отдельно и обновить страницу.

Импорт адаптирован к конкретной книге: восемь линий из строк 2–9 листа «кВ», данные «Т.О», «DATE», «АВК» и каталог всех 62 листов. Читаются сохранённые значения формул. Исходный файл не перезаписывается, VBA не запускается. Форма импорта произвольных книг пока не реализована.

Длина линии = в земле × 1,02 + ГНБ + в трубе × 1,01 + заводка. В сводку идёт сумма округлённых до метра длин отдельных линий. Этот расчёт воспроизводит предоставленную книгу; применимость коэффициентов к новым объектам необходимо подтвердить.

## Следующий этап для работы команды

1. Утвердить приоритетные печатные формы: журналы, инвентарная опись, АОСР, протоколы. Для каждой сопоставить поля книги с данными сервиса, перенести верстку и проверить на эталонном комплекте. Данные измерений вводятся отдельно, автоматически не придумываются.
2. Разобрать исходники VBA и перенести бизнес-правила, отделив их от оформления и управления листами.
3. Добавить участников и роли: администратор, инженер, проверяющий. Учётные записи, серверная проверка доступа к объектам, назначение задач и комментарии к документам.
4. Ввести версии документов и состояния «черновик → на проверке → возвращён / согласован». Сохранять снимок исходных данных при выпуске каждого документа.
5. Добавить загрузку паспортов, резервное копирование, восстановление, серверный экспорт в согласованные форматы. Затем развернуть на общем сервере с HTTPS и доступом команды.

Основная модель следующей версии: объект → участники, линии, материалы, этапы, измерения → документы → версии и согласования. Общие реквизиты хранятся один раз. Скрытые листы и неактуальные справочники не становятся рабочими данными автоматически.

## Проверки

`python3 -m unittest -v test_server.py` использует временную базу. Проверяет исходные длины, создание и сохранение, устойчивость чтения из базы, конфликт версий, отрицательные длины, обратные даты и отклонение стороннего Origin. `node --check public/app.js` проверяет синтаксис JavaScript.
